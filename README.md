# شَهْم — مساعدة على الطريق

نسخة متكاملة من تطبيق شَهْم باللغة العربية واتجاه RTL. تشمل واجهة الهاتف، تسجيل المستخدمين، طلبات مساعدة الطريق، صفحات الشهم والمستفيد، وظائف Supabase، وملفات تثبيت PWA.

## التعديلات المضمنة

- نافذة تثبيت وسط الشاشة مع خلفية مموهة؛ زر التسجيل بعد إغلاق النافذة يعمل وينقلك لاختيار الدور. يتذكر التطبيق إغلاق النافذة، ويخفي تذكير التسجيل بعد إكمال التسجيل أو تثبيت التطبيق.
- شعار شَهْم موحّد في أيقونة التطبيق وشاشة البداية وداخل التطبيق، مع ترويسة رئيسية بسيطة.
- واجهة عربية خضراء وكريمية، ترحيب وعبارات الصفحة الرئيسية، وشريط سفلي ثابت لا يغطي المحتوى.
- نموذج «طلب مساعدة عالطريق» يرسل نوع المشكلة ومسار البداية والوجهة والموعد وعدد الأشخاص والملاحظات. يرى الشهمون القريبون نوع المشكلة، لا الوصف وحده.
- بعد قبول الرحلة، تظهر للمستفيد بيانات الشهم ووسائل الاتصال وواتساب والمسافة المسجلة لحظة القبول، إضافة إلى نوع السيارة ولونها ورقمها.
- يلزم الشهم بإدخال بيانات السيارة والإقرار بصحتها ومسؤوليته عنها عند التسجيل. يمنع الخادم تغيير بيانات السيارة بعد تثبيتها.
- بطاقة طلب مختصرة بلا تكرار لمسار الرحلة، ومؤشر انتظار دائري للطلب المفتوح.
- ترحيل قاعدة موحّد، مع ترحيلات المصدر السابقة محفوظة في `supabase/legacy_migrations` للرجوع إليها.

## إعداد التطبيق

1. ثبّت Node.js ثم نفّذ `npm ci`.
2. انسخ `.env.example` إلى `.env` عند التطوير المحلي. يتطلب التطبيق `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`، ويعرض رسالة إعداد واضحة عند غيابهما. لا تضف مفتاح `service_role` أو أي مفتاح سري إلى التطبيق أو ملف ZIP.
3. شغّل `npm run dev`، أو أنشئ نسخة الإنتاج بـ `npm run build`.
4. لتسجيل الدخول بحساب Google، فعّل المزوّد في Supabase Authentication وأضف نطاق الموقع إلى Site URL وRedirect URLs.

## Supabase

المشروع المرتبط هو `xisotlcjtaiptabjdocp`. قاعدة الاختبار أُعيد تهيئتها بالفعل، وسجل الترحيلات يحتوي على `20260924144340_clean_shahm_baseline` و`20260924145616_remove_unused_create_trip_rpc`. لا حاجة لتطبيقهما مرة أخرى على هذا المشروع.

**تنبيه مهم:** يحتوي الترحيل الأساسي على `DROP SCHEMA public CASCADE` وحذف حسابات `auth.users`. يبدأ بحارس يرفض التنفيذ ما لم يكن المتغير `shahm.allow_destructive_baseline` مضبوطًا على `on` في جلسة قاعدة البيانات نفسها. استخدم الحارس فقط عند إعادة إنشاء قاعدة اختبار فارغة وقابلة للمسح. لتشغيله يدويًا على قاعدة اختبار عبر اتصال PostgreSQL واحد، اضبط `SET shahm.allow_destructive_baseline = 'on';` ثم نفّذ ملف الترحيل في الجلسة نفسها. عمليات `db push` المعتادة ستُرفض بأمان إذا لم يتوفر هذا الإعداد.

لا تستخدم `supabase db push` لإعادة تشغيل هذا الخط الأساسي؛ فالحارس يمنع تشغيله ضمن جلسة CLI عادية عمدًا. إن احتجت إلى إعادة بناء قاعدة اختبار، نفّذ الملف يدويًا عبر جلسة PostgreSQL واحدة بعد التأكد من المشروع وقابلية مسحه.

الوظائف المنشورة للمشروع:

- `create-trip-proxy`
- `notify-trip-accepted`
- `send-push`

تحذف وظيفة `notify-assistance-request` القديمة لأنها كانت مرتبطة بنموذج طلب مساعدة منفصل لم يعد التطبيق يستخدمه. تبقى الأسرار على Supabase؛ لا تضعها في ملفات الواجهة. تستخدم الوظائف متغيرات الخدمة التي يوفّرها Supabase، وتحتاج مفاتيح Web Push وإعدادات `ALLOWED_ORIGINS` في أسرار الوظائف.

## ملاحظات البيانات والخصوصية

- قاعدة الاختبار الآن بلا حسابات أو رحلات قديمة؛ سجّل حسابًا جديدًا للاستخدام.
- ينشئ خط الأساس 11 جدولًا أثناء تشغيله، ثم يحذف جدولي نموذج المساعدة القديمين في نهايته؛ فيبقى 9 جداول في `public` ولكل منها تفعيل RLS. يعرض `supabase_check.sql` العدد والقائمة الفعلية ويتحقق من RLS على كل جدول دون الاعتماد على عدد ثابت. بقيت مخططات Supabase الداخلية (`auth` و`storage` وغيرها) موجودة.
- يمكن للمستخدم تسجيل اشتراكات Push متعددة؛ لكل نقطة اتصال جهاز صف مستقل، وينتقل اشتراك المتصفح إلى الحساب المسجّل حاليًا. تُحذف الاشتراكات المنتهية لكل جهاز على حدة.
- يتضمن `20260924170000_multi_device_push_and_now_trip.sql` ترحيلًا إضافيًا لتحديث القواعد والاشتراكات في قواعد البيانات التي طُبّق عليها الخط الأساس سابقًا. راجع نتيجته على قاعدة اختبار قبل تطبيقه على أي مشروع حي.
- المسافة الظاهرة هي مسافة القبول المحفوظة، ولا تعرض إحداثيات الشهم الدقيقة.
- بيانات السيارة المحفوظة لا يتيح التطبيق تعديلها بعد الإقرار.
